스마트폰 PC 통계분석 웹앱 구현용 코딩 프롬프트
앱 이름: 데이터 한눈에
제출자: 은수현, 김정훈, 김응범

사용 방법
아래 지시문은 마스터 프롬프트를 실제 코드와 검산 절차로 구체화한 것이다.
AI에게 마스터 프롬프트, starter, 기준 데이터와 함께 제공하고 단계별로 적용한다.
실제 7주간의 대화 기록이 아니라 완성본 구현을 위한 재사용 가능한 개발 지시문이다.
한 단계가 끝나면 변경 파일·함수·확인 명령을 설명하고 다음 단계로 진행하라.

[공통 지시]
Python/Streamlit 기반 다중 파일 프로젝트를 구현해 줘. 화면 파일과 계산 파일을 분리해 줘.
결과를 임의 숫자로 채우지 말고 업로드 자료로 계산해 줘. ‘생략’, ‘추가 예정’, pass만 있는 함수를 남기지 마.
내부 계산에서는 정밀도를 유지하고 화면에서만 반올림해 줘.
실행할 수 있는 파일 전체와 requirements.txt, README.txt, sample.xlsx, tests, docs를 만들어 줘.
오류가 발생하면 원인·수정 파일·수정 내용·다시 확인할 명령을 설명해 줘.

1단계 파일 입력과 앱 뼈대
app.py에 Streamlit 페이지를 만들고 한국어 제목 ‘데이터 한눈에’를 표시해 줘.
기준 데이터와 내 파일 업로드를 선택하는 라디오 버튼을 만들고, 기준 데이터를 기본값으로 해 줘.
data_io.py에 read_data(raw, filename, sheet_name=0), excel_sheets(raw, filename)를 만들어 줘.
엑셀은 openpyxl/xlrd로, CSV는 UTF-8-SIG 또는 CP949로 읽어 줘.
헤더를 먼저 데이터로 읽어 중복/빈 열 이름을 탐지한 뒤 데이터프레임을 구성해 줘.
최대 10MB·10,000행·100열을 제한하고 빈 파일, 잘못된 확장자, 깨진 엑셀은 한국어 오류로 바꿔 줘.
미리보기 100행, 전체 사례·변수·빈칸 수, 열별 자료형과 결측 수를 보여 줘.
숫자로만 구성된 문자열 열은 수치형으로 변환하고, 문자가 섞인 열은 임의로 수치형으로 강제 변환하지 마.
최종 sample.xlsx에는 교수자의 36사례 기준 데이터를 복사하고 원래 starter 샘플은 data/starter_sample.xlsx에 보관해 줘.

2단계 공통 검증과 기초통계
analysis.py에 AnalysisError, numeric_series, _prepare, _fit, descriptive_statistics, frequency_table을 구현해 줘.
descriptive_statistics(df, columns)는 기존 starter의 ‘사용 사례 수(n)’와 ‘결측 수’ 열 이름을 유지해 줘.
평균·표본 표준편차·중앙값·최소·최대·범위·Q1·Q3·IQR을 계산해 줘.
빈칸과 ±무한대는 결측으로 취급하고 숫자가 아닌 비결측값은 명확히 오류로 처리해 줘.
표준편차 ddof=1을 사용하고 유효 사례가 1개면 표준편차를 0으로 만들지 마.
빈도표의 전체 비율은 전체 행 수를, 유효 비율은 비결측 행 수를 분모로 해 줘.
수치형 변수 여러 개와 빈도표 변수 1개를 선택하게 하고 히스토그램·막대그래프를 보여 줘.
_prepare는 선택 변수에 한해서 결측 행을 제거하고 n, dropped, total을 반환해 줘.

3단계 단순회귀와 다중회귀
regression(df, y, xs)를 구현해 줘. 절편을 포함한 statsmodels OLS를 사용해 줘.
선택한 열 이름을 내부 x0, x1 등으로 바꿔 사용자의 열 이름에 괄호·공백·const가 있어도 동작하게 해 줘.
화면에는 원래 열 이름을 복원해 줘. Y와 X 또는 X끼리 중복 선택을 막아 줘.
회귀식, R²·수정 R², B·SE·t·p·95% CI, VIF를 반환해 줘.
실제 사용 자료와 예측값·잔차도 반환하여 app.py에서 그래프를 그리게 해 줘.
행렬 순위를 확인하여 완전 공선성을 막고, n이 계수 수+1 이하인 모형을 거절해 줘.
Y나 X가 상수이거나 잔차 제곱합이 사실상 0이면 추정 한계를 설명해 줘.
VIF 5 이상을 주의 표시로 사용하되 자동으로 변수를 삭제하지 마.
단순회귀는 산점도+회귀선, 모든 회귀는 잔차-예측값 그래프와 Q–Q 그래프를 보여 줘.

4단계 일원분산분석과 이원분산분석
one_way_anova(df, y, group)를 구현해 줘.
2~20집단, 각 집단 2사례 이상을 확인하고 Y ~ C(G) 모형을 적합해 줘.
SS, df, MS, F, p를 보여 주고 η²=SS효과/SS전체, ω²=(SS효과−df효과×MS오차)/(SS전체+MS오차)를 계산해 줘.
교육용 표시에서는 음수 ω²를 0으로 제한하되 문서에 이 규칙을 기록해 줘.
Tukey HSD의 집단 쌍·평균차(집단2−집단1)·보정 p·신뢰구간·유의 여부를 표로 만들어 줘.
사후검정의 반올림된 summary 문자열 대신 결과 배열의 원시 수치를 사용해 줘.
Levene 검정을 중앙값 기준으로 실시하고 등분산 위반 가능성을 안내해 줘.

two_way_anova(df, y, factor_a, factor_b, ss_type=2)를 구현해 줘.
모든 조합의 사례 수를 교차표로 검사하고 0개 또는 1개인 조합을 거절해 줘.
내부 안전한 이름 A·B·Y로 바꾸어 Y ~ C(A, Sum) * C(B, Sum)을 적합해 줘.
Type II 기본값과 Type III 선택을 제공하고 절편 행은 효과 표에서 제외해 줘.
A·B·A×B 각각의 부분 η²=SS효과/(SS효과+SS오차)를 계산해 줘.
오차 행에는 효과크기와 p를 표시하지 마. 집단별 평균 상호작용 그래프를 만들어 줘.
불균형 설계, 상호작용 유의 시 주효과 해석, 반복측정 미지원에 대한 안내를 붙여 줘.

5단계 매개효과와 조절효과
mediation(df, x, mediator, y, n_boot=2000, seed=42)를 구현해 줘.
유효 사례 최소 10개, 서로 다른 수치형 변수 3개를 요구해 줘.
M~X에서 a, Y~X+M에서 b와 c′, Y~X에서 c를 계산해 줘.
ab를 간접효과로 반환하고 c와 c′+ab가 수치상 일치하는지 검산해 줘.
NumPy default_rng(seed)로 행 단위 재표집을 수행하고 각 재표집에서 a와 b를 다시 추정해 줘.
재표집 모형의 행렬 순위가 부족하면 제외하고, 유효 반복이 요청 횟수의 90% 미만이면 오류 처리해 줘.
분포의 2.5%, 97.5% 분위수를 percentile 95% CI로 사용하고 분포 그래프를 보여 줘.
2,000·5,000·10,000회 선택, 시드 입력, 유효 반복 수를 제공해 줘.
부트스트랩 CI를 정규이론 CI나 BCa라고 부르지 마.

moderation(df, x, moderator, y, center=True)를 구현해 줘.
전체 완전사례에서 평균을 계산한 뒤 Xc, Wc, Xc×Wc를 구성해 줘.
Y~Xc+Wc+Xc×Wc 모형과 상호작용 없는 축소 모형을 적합하여 ΔR²를 구해 줘.
중심화를 해제하면 원점수 X, W, X×W를 사용해 줘.
W의 원점수 평균±표본 SD, 평균에 해당하는 기울기를 Bx+Bxw×Wc로 계산해 줘.
대비벡터 [0,1,0,Wc]와 모형 공분산을 사용해 SE, t, p, CI를 구해 줘.
W 원점수 수준과 관측 범위 내 여부를 표시하고, X의 관측 범위 내에서 3개 예측선을 그려 줘.
세 단순기울기의 p는 다중검정 보정 전 값임을 안내해 줘.

6단계 화면과 내보내기
app.py는 각 분석 설정을 읽고 분석 실행 버튼을 누를 때 계산하게 해 줘.
계산된 결과는 세션에 저장하되 원본 파일·시트·분석 종류·변수·반복 횟수·시드·중심화 설정이 바뀌면 숨겨 줘.
모형 분석 결과 상단에 전체·사용·제외 사례 수를 반드시 표시해 줘.
statsmodels의 원시 예외를 사용자에게 그대로 노출하지 말고 사용자 입력 오류와 예상 밖 오류를 구분해 줘.
예상 밖 오류는 콘솔에 남기고 화면에는 원본과 설치 환경을 확인하라는 안내를 보여 줘.
네이비와 민트 포인트의 대시보드로 구성하고 작은 화면에서 제목·버튼·그래프가 잘리지 않게 해 줘.
st.dataframe은 컨테이너 폭에 맞추고 넓은 표는 내부 스크롤을 허용해 줘.
결과표는 export_excel(tables, summary)로 XLSX로 저장하고 해석·분석 설정은 UTF-8-SIG TXT로 내려받게 해 줘.
ExcelWriter에는 openpyxl을 쓰고 사용자 문자열은 수식이 아닌 문자열 셀로 저장해 줘.
화면 p값은 .001보다 작으면 ‘< .001’로 표시하되 다운로드에는 실제 계산값을 남겨 줘.

7단계 검산과 마감
tests/test_analysis.py에 다음 교수자 기준값을 대조하는 테스트를 작성해 줘.
기준표의 마지막 자릿수 절반을 절대 허용오차로 사용하고, p=0.000000은 정확한 0이 아니라 반올림된 매우 작은 값으로 처리해 줘.

기초통계: score n=36, 평균=76, SD=8.135, 중앙값=76, 최소=60, 최대=92.
단순회귀: score~study_time, R²=.0330, 절편=72.4268, B=1.1089, p=.288707.
다중회귀: score~study_time+pre_score, R²=.9349, 수정 R²=.9310,
study_time B=.0729, p=.792724, pre_score B=.8912, p<.0000005.
일원분산: anova_score~method, F=14.0291, p=.000039,
집단 평균 A=55.166, B=58.193, C=62.407.
이원분산: anova_score~method*grade, method F=266.3419, grade F=283.2311,
상호작용 F=8.2607, p=.000174.
매개: med_x→med_m→med_y, a=.8027, b=1.5300, c′=.1383, ab=1.2282.
조절: mod_y~mod_x+mod_w+mod_x*mod_w, 상호작용 B=.6786, p<.0000005, R²=.9743.

추가로 NumPy 최소제곱과 SciPy f_oneway를 이용하여 일부 계산을 독립 대조해 줘.
중심화 불변성, 매개 경로 항등식, seed 재현성, 선택하지 않은 열의 결측 무영향을 검사해 줘.
중복 변수·상수·문자 혼입·완전 공선성·표본 부족·빈 집단 조합·잘못된 파일·CSV 인코딩을 검사해 줘.
tests/test_app.py에서는 AppTest로 7개 메뉴를 각각 실행하고 표·오류·설정 변경 후 결과 초기화를 확인해 줘.
python -m pytest -q tests를 실제로 실행하고 성공 수와 경고·실패가 있으면 기록해 줘.
기준값/실제값/오차/판정 표를 docs에 저장해 줘. 불일치가 있으면 숨기지 말고 원인을 써 줘.
README에 Windows PowerShell·macOS 명령, 같은 Wi-Fi 스마트폰 접속, 문제 해결, 변수 선택 예시를 넣어 줘.
검증 가능한 화면 캡처가 확보되면 포함하고 실제 스마트폰 접속 여부는 별도로 명시해 줘.
개발 및 수정 기록에는 실제 수행한 내용만 적고 임의의 팀원 역할·활동 날짜·사용자 경험을 만들지 마.
가상환경·캐시·개인 경로·비밀정보를 제외하고 소스 ZIP의 압축 무결성을 확인해 줘.

8단계 Python 호환성과 실행 편의성 보완
팀원은 은수현, 김정훈, 김응범이다. 제출 파일명과 앱·문서 표기를 모두 맞춰 줘.
64비트 CPython 3.9~3.14를 대상으로 하고 Streamlit이 제외한 3.9.7은 제외해 줘.
requirements.txt의 단일 버전 고정을 검증한 범위 지정으로 바꿔 해당 Python에 맞게 설치되게 해 줘.
pytest는 requirements-dev.txt로 분리하고 Python별 실제 설치 조합은 docs/locks에 보관해 줘.
표준 라이브러리만 사용하는 start.py를 만들어 버전 검사, 버전별 가상환경 생성, 패키지 설치, 앱 실행을 연결해 줘.
기본은 PC 전용 주소, --lan이면 같은 Wi-Fi 접속, --setup-only면 설치만, --test면 자동 검사, --check면 지원 여부만 확인하게 해 줘.
전역 패키지와 기존 .venv를 변경하지 말고, 준비된 환경은 재사용해 줘. 요구사항이 바뀌거나 설치가 불완전하면 재확인해 줘.
Windows bat와 macOS command/sh 실행 파일에서 설치된 지원 버전을 찾아 실행하게 해 줘.
한글·공백 경로에서 최초 설치와 재실행을 실제로 검증하고, 3.9~3.14 각각에서 통계 및 UI 테스트를 실행해 줘.
실제로 실행한 OS·Python 버전과 미검증 플랫폼을 구분해서 보고하고, 모든 Python 버전에서 무조건 된다고 표현하지 마.

9단계 GitHub와 Streamlit Community Cloud 연동
저장소 최상위에서 app.py와 requirements.txt를 바로 찾을 수 있도록 소스를 정리해 줘.
README.md에 조원 이름, 분석 기능, 로컬 실행법, 검산 결과, GitHub와 실행 서버의 역할을 적어 줘.
docs/GITHUB_DEPLOY.md에는 저장소 생성, 소스 업로드, main/app.py 선택, Python 3.12 예시, 실행 URL 확인 절차를 넣어 줘.
로컬 실행은 기존 3.9~3.14 지원을 유지하고, 배포된 앱 이용자는 Python을 설치하지 않아도 된다고 설명해 줘.
.gitignore에 .venv*, __pycache__, .pytest_cache, .env, .streamlit/secrets.toml, uploads, private_data를 제외해 줘.
.github/workflows/tests.yml에서 Python 3.9~3.14 행렬로 requirements-dev.txt 설치와 pytest 검사를 실행해 줘.
검사에는 저장소 읽기 권한만 사용하고 사용자 비밀번호·토큰을 코드에 넣지 마.
앱의 안내 문구에서 업로드 파일을 처리하는 위치를 내 PC 또는 배포 서버로 정확히 구분해 줘.
마스터·코딩 프롬프트도 소스의 prompts 폴더에 포함하고 기존의 두 제출 ZIP을 갱신해 줘.
저장소 생성, 업로드, 배포, 배포 앱 시연은 실제 수행한 단계까지만 기록해 줘.

[오류가 생겼을 때 이어서 사용할 프롬프트]
방금 실행한 단계: [단계 번호]
오류가 나온 파일과 명령: [파일명, 실행 명령]
오류 메시지: [개인정보를 지운 오류 전문]
원인을 한국어로 쉽게 설명하고, 수정할 파일·함수와 수정 코드를 보여 줘.
다른 분석 기능이 바뀌지 않았는지 검사한 뒤 재실행 명령과 기대 결과를 알려 줘.
검산 수치를 맞추려고 결과를 강제로 덮어쓰지 말고 결측 처리·모형·제곱합 방식·반올림·버전을 확인해 줘.

[인터페이스 마무리]
ui.py의 inject_styles, render_header, section_title, analysis_hint, render_empty_result, render_footer로 화면 요소를 분리해 줘.
assets/styles.css에 반응형 스타일을, assets/insight.svg에 장식 그래픽을 두고 앱과 함께 배포해 줘.
CSS는 st.html의 스타일 전용 블록으로 넣고, 그래픽은 이미지로 표시해 SVG 요소가 HTML 정제 과정에서 빠지는 문제를 피하게 해 줘.
st.container의 명시적 key와 기본 입력 위젯을 사용하고, 상단 패딩은 고정 도구막대 높이보다 크게 확보해 줘.
분석 설정 카드에 해당 분석의 목적을 한 문장으로 알려 주고, 실행 전에는 결과가 나타날 위치를 안내해 줘.
기존 계산 함수·설정 키·다운로드 구조를 유지하고 기존 AppTest와 통계 테스트를 실행해 줘.
브라우저에서 PC 배치, 320px·390px 세로 배치, 가로 넘침과 제목 잘림을 확인한 뒤 GitHub와 두 제출 ZIP에 반영해 줘.
