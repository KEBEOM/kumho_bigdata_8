스마트폰 PC 통계분석 웹앱 개발 마스터 프롬프트
과제명: AI와 함께 만드는 데이터분석용 웹앱
앱 이름: 데이터 한눈에
제출자: 은수현, 김정훈, 김응범

이 문서는 앱의 목표, 분석 범위, 개발 원칙과 완료 기준을 정의하는 상위 지시문이다.
구체적인 구현 지시는 함께 제출한 02_앱개발용_코딩_프롬프트.txt를 따른다.
첨부 설명서와 starter, 교수자 기준 데이터를 바탕으로 다음 요구사항을 충족하는 앱을 개발해 줘.

1. 역할과 목표
너는 Python 웹앱 개발자이자 교육용 통계분석 도구 설계자다. 나는 코딩을 배우는 학생이다.
PC에서 실행하고 같은 Wi-Fi의 스마트폰 브라우저에서 접속하며, GitHub 저장소와 Streamlit Community Cloud 배포도 지원하는 한국어 웹앱을 만들어라.
엑셀 자료를 업로드하면 기초통계, 단순·다중회귀, 일원·이원분산분석, 매개·조절효과를 계산하고 결과를 쉽게 설명해야 한다.
실행 중 생성형 AI API나 API 키가 없어도 동작해야 한다. AI는 개발 과정의 조력자로 사용한다.
앱 이름은 ‘데이터 한눈에’로 정하고, 실제 계산과 표·그래프·다운로드까지 구현하라.
계산 결과를 고정해 보여 주는 시연용 화면이나 ‘추가 예정’ 버튼으로 대체하지 마라.

2. 입력 자료와 기준 자료
우선 제공된 final_starter의 파일 구조와 기본 함수를 읽어라. 원본은 별도로 보관하라.
학생용 설명서의 분석 범위와 주차별 AI 프롬프트를 구현 요구사항으로 삼아라.
검산에는 추가자료의 01_통계앱_기준데이터.xlsx와 02_기준결과_검산표.md를 사용하라.
36사례 기준 데이터를 최종 앱의 sample.xlsx로 제공하고 12사례 원래 starter 자료도 별도로 보관하라.
샘플은 제공된 가상 자료이며, 실제 학생 이름·학번·전화번호 등의 개인정보를 추가하지 마라.

3. 기술과 구조
64비트 CPython 3.9~3.14(Streamlit이 제외한 3.9.7은 제외), Streamlit, pandas, NumPy, SciPy, statsmodels, openpyxl, xlrd, Plotly를 사용하라.
pytest와 Streamlit AppTest로 계산과 화면 흐름을 확인하라.
app.py는 화면·선택·결과 표시를, analysis.py는 통계 계산과 분석 검증을 맡게 하라.
data_io.py는 파일 읽기·열 이름 검사·결과 엑셀 내보내기를 맡게 하라.
requirements.txt는 Python별로 호환 버전을 선택할 수 있도록 검증한 버전 범위를 사용하라. 실제 설치 버전은 Python별 잠금 파일과 호환성보고서에 기록하라. 테스트 도구는 requirements-dev.txt로 분리하라.
start.py에서 현재 Python 지원 여부를 확인하고 버전별 가상환경 준비·최초 패키지 설치·앱 실행을 자동으로 수행하라. Windows와 macOS/Linux 실행 파일을 함께 제공하라.
시스템 Python 패키지를 수정하지 말고, 다시 실행할 때 설치 상태를 확인해 정상 환경을 재사용하라.
README.txt, sample.xlsx, tests, docs, .streamlit/config.toml을 함께 제공하라.
중요 함수에는 한국어 설명 또는 주석을 넣고 불필요한 서버·데이터베이스·로그인을 추가하지 마라.

4. 데이터 준비
.xlsx, .xls, .csv를 지원하고, 엑셀은 시트를 선택하게 하라.
CSV는 UTF-8과 CP949를 지원하라. 첫 행은 비어 있지 않은 고유한 열 이름이어야 한다.
최대 10MB, 10,000행, 100열로 제한하고 범위를 넘으면 이유를 알려라.
파일을 업로드하지 않아도 ‘기준 데이터로 연습’을 선택해 앱을 바로 시험할 수 있어야 한다.
자료 미리보기, 총 사례 수, 변수 수, 빈칸 수와 변수 유형을 보여라.
숫자로만 구성된 열은 숫자로 읽되 숫자 열에 문자가 섞이면 임의로 지워서 분석하지 마라.
빈칸과 무한대는 결측으로 처리하되 이 규칙을 화면과 README에 명시하라.
기초통계는 변수별 유효 사례를 사용하고, 모형 분석은 선택 변수의 완전사례만 사용하라.
분석 결과마다 전체·사용·제외 사례 수를 보여라. 선택하지 않은 열의 결측 때문에 행을 제외하지 마라.

5. 필수 분석 기능
5-1. 기초통계
수치형 변수의 n, 결측, 평균, 표본 표준편차(n−1), 중앙값, 최소·최대, 범위, Q1, Q3, IQR을 보여라.
범주형 변수의 빈도, 전체 비율, 유효 비율을 구분하라. 결측 빈도도 표시하라.
수치형 변수는 히스토그램, 범주형 변수는 막대그래프를 제공하라.

5-2. 단순회귀와 다중회귀
수치형 Y 1개와 X 1개 또는 2~10개를 선택하게 하라.
절편 포함 OLS를 적합하고 회귀식, R², 수정 R², B, SE, t, p, 95% 신뢰구간을 표시하라.
VIF, 잔차와 예측값 그래프, 잔차 Q–Q 그래프를 제공하라. 단순회귀에는 산점도와 회귀선도 보여라.
Y와 X 중복, 상수 변수, 표본 부족, 완전 다중공선성, 오차가 거의 0인 모형을 검사하라.

5-3. 일원분산분석
수치형 Y와 집단변수를 선택하고 집단별 n·평균·표준편차를 보여라.
제곱합, 자유도, 평균제곱, F, p, η², ω²와 Tukey HSD 사후비교를 제공하라.
집단별 상자그림과 중앙값 기준 Levene 등분산 검정을 제공하라.
2~20개 집단, 집단당 2사례 이상을 허용하라. 3집단 이상 비교를 기준 데이터로 검산하라.
등분산 가정 위반 가능성과 사후검정의 한계를 명확하게 안내하라.

5-4. 이원분산분석
수치형 Y, 서로 다른 요인 A·B를 선택하게 하라. 모든 A×B 조합에 최소 2사례를 요구하라.
A, B, A×B의 F, 자유도, p, 부분 η², 집단별 평균과 상호작용 그래프를 보여라.
Type II를 기본값으로 하여 교수자 정답표와 비교하고, Sum coding 기반 Type III도 선택할 수 있게 하라.
상호작용 유의 시 주효과만으로 결론 내리지 않도록 안내하라. 불균형 설계와 반복측정 적용 제한을 설명하라.

5-5. 매개효과
수치형 X, M, Y가 서로 달라야 한다. 동일한 완전사례로 모든 경로를 추정하라.
a, b, c, c′, 간접효과 a×b를 보여라.
행을 함께 재표집하는 쌍 부트스트랩으로 간접효과의 percentile 95% 신뢰구간을 계산하라.
기본 2,000회, 선택 5,000·10,000회, 기본 시드 42로 재현 가능하게 하라.
특이 재표집은 제외하고 유효 반복 수를 보여라. 실패가 10%를 초과하면 오류로 안내하라.
신뢰구간의 0 포함 여부로 통계적 근거를 설명하고, 인과적 매개나 완전·부분 매개를 단정하지 마라.

5-6. 조절효과
수치형 X, W, Y를 선택하고 Y ~ X + W + X×W를 추정하라.
X·W 평균 중심화를 기본으로 하고 해제도 허용하라.
상호작용 B, SE, t, p, 신뢰구간, R², 수정 R², 상호작용 추가 ΔR²를 표시하라.
W의 평균과 평균±1 표본 SD에서 단순기울기, SE, t, p, 95% CI와 예측선을 보여라.
원점수 W 수준을 표시하고 관측 범위 밖의 값은 외삽으로 안내하라.
중심화 여부에 따라 상호작용 계수·예측값·R²가 유지되는지 검증하라.

6. 해석과 화면
‘데이터 준비 → 분석 설정 → 분석 결과 → 결과 가져가기’ 순서로 구성하라.
한국어 제목·설명·오류 안내를 사용하고 스마트폰에서 입력 요소가 세로로 자연스럽게 배치되게 하라.
큰 표는 내부 가로 스크롤을 허용하고 결과표를 엑셀로 내려받게 하라.
유의수준은 .05, 신뢰구간은 95%로 명시하라. 매우 작은 p는 ‘< .001’로 표시하고 0이라고 쓰지 마라.
p값과 함께 효과크기·계수·신뢰구간을 해석하라. 유의하지 않음을 ‘차이가 없다’고 단정하지 마라.
통계적 관계를 원인과 결과로 설명하지 마라. 자동 해석은 조건에 따른 안내 문장으로 작성하라.
파일·분석·변수·설정이 바뀌면 이전 결과를 숨겨 잘못된 결과를 가져가지 않게 하라.
결과표 XLSX와 설정·해석 TXT 다운로드를 제공하고 원시 수치는 반올림하지 않은 채 보존하라.
내보낸 엑셀의 외부 문자열을 실행 가능한 수식으로 기록하지 마라.

7. 검증과 제출
교수자 기준값을 앱에 하드코딩하지 마라. 예상값은 테스트와 검산표에서만 사용하라.
기초통계·회귀·ANOVA·매개·조절을 실제로 실행하여 기준표의 반올림 정밀도 내에서 일치하는지 확인하라.
정상 입력 외에 잘못된 파일·빈 자료·중복 머리글·문자 혼입·결측·상수·부족한 표본·집단 부족도 검사하라.
실행한 검사와 실행하지 못한 검사를 구분하라. 실제 스마트폰 접속을 하지 않았다면 했다고 쓰지 마라.
개발 단계와 실제 수정 내용을 기록하되, 존재하지 않는 대화·팀원 역할·7주 활동 기록을 만들지 마라.
앱의 한계, 설치 방법, PC 실행, 동일 Wi-Fi 스마트폰 접속, 검산 방법, 발표 순서를 문서화하라.
최종적으로 마스터 프롬프트와 코딩 프롬프트 두 문서를 하나의 ZIP으로, 실행 가능한 소스 폴더를 별도의 ZIP으로 제공하라.

8. 완료 기준
두 제출 파일의 이름은 ‘은수현_김정훈_김응범_마스터와 코딩.zip’, ‘은수현_김정훈_김응범_소스.zip’으로 한다.
팀원 이름은 은수현, 김정훈, 김응범 순서로 파일명과 앱·문서에 반영하라.
코드만 작성했다고 끝내지 말고 실제 검산 결과, 테스트 결과, 실행 안내와 남은 확인 사항까지 제시하라.

9. GitHub 연동과 온라인 배포
소스 파일을 GitHub 저장소 최상위에 올릴 수 있게 정리하고 한국어 README.md와 배포 안내를 작성하라.
app.py를 Streamlit 배포 진입점으로, requirements.txt를 의존성 목록으로 사용하라. start.py는 로컬 실행기에 한정하라.
배포 서버에서 Python 3.12를 선택하는 예시를 제공하되 이용자의 Python 설치가 필요 없고 로컬 버전 지원과 별개임을 설명하라.
.gitignore로 가상환경, 캐시, 비밀번호·토큰, 업로드 자료를 제외하라.
GitHub Actions에서 Python 3.9~3.14의 통계·화면·실행기 테스트를 실행하도록 구성하라.
업로드 자료는 로컬 실행 시 내 PC, 클라우드 접속 시 배포 서버에서 계산됨을 정확히 안내하라.
실제 생성한 저장소 URL과 배포 성공 후의 실행 URL만 기록하고, 계정 연결·배포·원격 검사를 하지 않았다면 완료했다고 쓰지 마라.
